# Sub2API File Reference Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a MinIO/S3-backed file upload flow so `/responses` and related inference endpoints can accept `file_id` references instead of large inline image payloads, while preserving a bounded compatibility path for legacy base64 image clients.

**Architecture:** Add a storage abstraction plus file metadata model, expose upload-session endpoints, and resolve `file_id` references inside existing gateway request handlers before upstream forwarding. Keep legacy inline `data:image/...` support only as a compatibility path with explicit size thresholds and clear migration errors. Validate the full flow under both `Docker Compose` and `systemd + binary` deployment modes.

**Tech Stack:** Go, Gin, Ent, PostgreSQL, Redis, MinIO/S3-compatible object storage, Docker Compose, systemd, Go test, pnpm/vitest, git
